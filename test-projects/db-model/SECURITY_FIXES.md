# 安全修复和改进日志

## 🔒 重要安全修复

### 1. 修复密码更新安全漏洞（严重）✅

**问题描述**：
之前使用 `findOneAndUpdate` 或 `updateOne` 方法更新密码时，`pre('save')` 中间件不会被触发，导致密码以明文形式存储到数据库中。

**修复方案**：
- 添加了 `pre('findOneAndUpdate')` 中间件
- 添加了 `pre('updateOne')` 中间件
- 创建了统一的 `hashPassword` 辅助函数
- 正确处理了 `$set` 操作符的情况

**修复代码位置**：`User.js` 第 71-123 行

---

### 2. 增强密码强度验证 ✅

**改进前**：
- 最小长度：6 个字符
- 无密码复杂度要求
- 允许弱密码如 "123456", "aaaaaa"

**改进后**：
- 最小长度：8 个字符
- 必须包含大写字母
- 必须包含小写字母
- 必须包含数字
- 使用正则表达式验证：`/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/`

**修复代码位置**：`User.js` 第 34-41 行

---

### 3. 改进邮箱格式验证 ✅

**改进前**：
使用简单的正则表达式：`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`

**问题**：
- 允许连续的点（如 `test..user@example.com`）
- 允许无效的域名格式
- 验证不够严格

**改进后**：
使用更严格的正则表达式：
```regex
/^[a-zA-Z0-9]([a-zA-Z0-9._-]*[a-zA-Z0-9])?@[a-zA-Z0-9]([a-zA-Z0-9-]*[a-zA-Z0-9])?(\.[a-zA-Z0-9]([a-zA-Z0-9-]*[a-zA-Z0-9])?)*\.[a-zA-Z]{2,}$/
```

**验证规则**：
- 本地部分必须以字母或数字开头和结尾
- 域名部分必须以字母或数字开头和结尾
- 不允许连续的特殊字符
- 顶级域名至少2个字符

**修复代码位置**：`User.js` 第 23-29 行

## 📝 使用建议

### 生产环境配置

在生产环境中建议设置以下环境变量：

```bash
# .env 文件
BCRYPT_SALT_ROUNDS=12
```

### 密码更新最佳实践

**推荐方式**（使用 save）：
```javascript
const user = await User.findOne({ username: 'testuser' });
user.password = 'NewPassword123';
await user.save();
```

**也可以使用**（使用 findOneAndUpdate）：
```javascript
await User.findOneAndUpdate(
  { username: 'testuser' },
  { password: 'NewPassword123' },
  { new: true, runValidators: true }
);
```

现在两种方式都是安全的！
